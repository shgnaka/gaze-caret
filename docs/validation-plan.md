# gaze-caret 検証計画

版: 0.1 / 作成日: 2026-09-05

[要件定義](requirements.md) の受け入れ条件を検証する。本書は計画であり、実装・テストの実施状況は [README](../README.md) と各 PR の記録を参照する。本人のカメラによる精度測定はまだない。

## 1. 判定を分ける

| 判定 | 必要な証拠 |
| --- | --- |
| M0 のソフトウェア完成 | 下記の自動受け入れテスト、カメラの手動確認、再現可能な配布物と操作説明 |
| M0 の実験完了 | 本人のカメラを使った独立した評価と、失敗を含む全試行のレポート |
| M1 へ進むか | M0 の精度・失敗・負荷と、改善可能性の判断を記録した決定 |
| M2 へ進むか | M1 で従来操作と比べた、成功率・選択完了時間・修正回数・校正負担の評価 |

自動テストが緑でも視線精度が良いとは言えない。反対に、精度が足りないという実験結果も、失敗を正しく測れていれば有効な成果である。

## 2. 初期の実験設定

次は比較の出発点であり、精度や性能が保証された値ではない。実装は設定を記録・変更できるようにし、正式評価の途中では固定する。

| 設定 | 初期値・規則 |
| --- | --- |
| カメラ | 映像のみ。640 × 480、30 fps を希望値として要求。実際に採用された設定を記録する。 |
| 推論頻度 | 上限 15 回 / 秒を初期値とする。バックログを作らず、実効頻度を測る。 |
| 校正点 | 表示領域の幅・高さの 10 % / 50 % / 90 % の組による 9 点。画面の遮蔽物と重ならないレイアウトにする。 |
| 校正の収集 | 順序を変えた 2 巡。点の提示後 300 ms を除外し、続く最大 1,000 ms から、各提示につき有効な 5〜15 サンプルを採る。不足した提示だけ再試行する。 |
| 学習の均等化 | 点ごとの寄与を等しくする。全点の収集データを保持し、校正サンプルは 9 × 2 × 15 = 270 件以内とする。再試行は不足した提示のデータを置き換える。 |
| 回帰の初期方式 | 特徴量を学習データの統計量で標準化し、切片付きリッジ回帰を使う。切片は正則化しない。損失を残差平方和 + λ × 係数平方和と定義し、λ = 1 から始める。 |
| 履歴 | 最大 1,000 ms、最大 60 件。時刻と件数のどちらかの上限で古い値を破棄する。 |
| 押下前の選択窓 | 押下の 250 ms 前から 50 ms 前まで、両端を含む。取得に近い時刻で窓を選び、押下時点で到着済みの結果だけを使う。 |
| 必要サンプル数 | 同じ contextId / modelId の有効な 3 件以上。窓内になければ位置なし。 |
| 代表点と分散 | x / y の中央値。各軸について中央値からの絶対偏差の中央値を求め、どちらかが 40 CSS px を超えたら分散過大とする。 |
| 行候補 | 点から各行矩形までの最短ユークリッド距離。同距離は DOM 順。最短距離が基準行ピッチの 2 倍を超えたら候補なし。 |
| 評価用の文章 | 主条件は日本語横書き、font-size 16 CSS px、line-height 24 CSS px、1 段組・複数段落。別条件として line-height 32 CSS px を比較し、混ぜて集計しない。 |
| 反応速度の仮目標 | 有効な位置を決定した試行で、キー処理開始から表示反映の近似時刻までの p95 が 100 ms 以下。カメラ取得からの全遅延とは区別する。 |

初期方式の追加フィルターはなし。顔検出器に不可避の平滑化がある場合は版と設定を記録する。別方式を比較する際に、内部のフィルターと外部の中央値処理を区別する。

均等化の初期方式は、点ごとの有効サンプル数を最少件数へそろえてから学習するものとする。収集時刻に偏らない間引きを行い、その選択を seed から再現可能にする。標準化と回帰には、この同じ学習用サンプル集合を使う。収集した全点のデータは、件数上限の範囲で分析用に保持する。

中央値は偶数件の場合、中央の 2 値の平均とする。無効値を加えて必要数を満たしたり、窓を自動的に広げて古い位置を採用したりしない。完全に同じフレームの重複処理を別サンプルとして数えない。

## 3. 自動受け入れテスト

実装段階では、本節の観測可能な結果に対するテストを先に作る。実装の内部関数名やファイルの有無だけを検査するテストにはしない。時計、カメラ、検出結果、座標、DOM fixture を制御できる境界を用意する。

| ID | 対応要件 | 条件と確認する結果 |
| --- | --- | --- |
| A-01 | CAM-01, CAM-04 | 初期表示ではメディア要求 0 回。開始後の要求は video のみ。拒否・デバイスなし等で理由と再試行が表示され、未処理の例外を残さない。 |
| A-02 | CAM-02, CAM-03, DATA-04 | 起動連打、許可待ち中の停止、停止後に返るストリーム、推論中の停止、非表示化、再開始を試す。古い全トラックが終了し、以前の結果が UI や履歴へ復帰しない。 |
| A-03 | EST-01, EST-03, CAL-02 | 既知の低次元の対応関係から学習し、学習に未使用の入力で座標を回復できる。切片、特徴量のスケール差、一定値の列、相関した列でも有限値を返す。正則化の影響を考慮した期待値・許容誤差を独立に定める。 |
| A-04 | EST-02, EST-04 | 既知の特徴点配置を使い、画像サイズ・平行移動・傾きに対する相対座標を確認する。左右反転の扱いを確認し、欠損、閉眼、複数人、NaN などが有効な位置にならないことを確認する。 |
| A-05 | EST-05, EVAL-03 | 遅い検出器を注入しても推論の同時実行が 1 件を超えず、キューが成長しない。取得時刻と完了時刻が区別され、計測時間に処理待ちを隠さない。 |
| A-06 | CAL-01, CAL-02, DATA-03 | 点の切り替え前に取得して後から届いた結果や、点の提示直後の結果を誤った点へ割り当てない。点ごとの不足を検出し、全点を保持して件数・寄与を制限する。 |
| A-07 | CAL-03, EVAL-02 | 検証中にクリック・移動・正解表示を行っても学習データとモデルが変わらない。前処理の統計量にも検証データを混ぜない。評価中の点と顔プレビューが非表示である。 |
| A-08 | POS-01, POS-04, CAL-04 | 校正・停止・カメラ・表示領域の変更で古い文脈が無効になる。スクロールで履歴を破棄するが、表示領域が同じなら校正まで無条件に失わない。レイアウト変更中の試行には中断理由が付く。 |
| A-09 | POS-02, POS-03 | 制御した時刻で時間窓の両端、3 件の下限、中央値、分散の閾値を確認する。押下後に到着した結果を使わず、過去 60 件 / 1,000 ms の上限を超えない。位置なしの理由が区別できる。 |
| A-10 | TXT-01, TXT-02 | 複数段落・余白・同距離を持つ DOM fixture で、定義した距離・上限・同距離規則に従う。評価の正解だけを変えても同じ入力座標への候補は変わらず、目標や結果の強調で行矩形が変わらない。 |
| A-11 | TXT-03 | 検証エリアで通常の Space を受け付け、入力欄、contenteditable、ボタン、修飾キー、IME、repeat では評価試行を作らない。候補なしで既存の選択を変更しない。 |
| A-12 | EVAL-01, EVAL-03 | 正解、隣接行、別の行、別の段落、位置なし、中断が既知の試行集合を集計し、件数・分母・分位点が定義どおりになる。欠損値を誤差 0 と数えない。 |
| A-13 | EVAL-04, DATA-02, DEV-04 | JSON と CSV から試行結果・設定・環境を再集計でき、null と 0 を区別できる。日本語、引用符、改行を含む理由の出力、保存失敗と再試行を確認する。 |
| A-14 | DATA-01, DATA-02, DATA-03, DATA-04 | 通信とブラウザ保存先を観測し、画像・音声・特徴量・視線の自動保存や送信がないことを確認する。明示エクスポートの対象は許可された数値・メタデータだけ。全データ破棄後に古い処理が復元しない。 |
| A-15 | DEV-01, DEV-02, DEV-03 | クリーンな環境で固定依存から自動検証・ビルドが成功する。配布物を展開して localhost で起動し、同梱されたモデル・WASM を読み込める。API キーや専用 GPU を要求しない。 |

A-04 は特徴量計算や異常時の処理の正しさを調べる。MediaPipe の実写上の検出精度を、人工的な特徴点だけで証明するものではない。

## 4. 本人のカメラを使う手動確認

| ID | 確認すること |
| --- | --- |
| H-01 | 新規の許可取得、拒否からの再試行、カメラ選択、映像のみの取得、停止・タブ非表示時のトラック解放。他アプリが使っている場合はアプリのトラック状態を確認する。 |
| H-02 | 明るさ、眼鏡の反射、顔が画面外に出る、目を閉じる、再開、姿勢変更について、表示される理由と挙動が理解できる。顔検出成功を視線の正確さと取り違える表示がない。 |
| H-03 | Chrome で配布物の説明どおりに開始・校正・評価・書き出し・停止を完了できる。Vivaldi は同じ確認を行い、結果を別に記録する。 |
| H-04 | 少なくとも 10 分の実行で実効推定頻度と遅延の推移を記録する。ブラウザのタスク管理等で CPU 使用率・メモリ・操作の引っかかりを確認し、測定条件も残す。 |

カメラのランプがある機器では点灯・消灯も確認する。ランプだけを全トラック解放の証明にはしない。消費電力の定量評価は同じ明るさ・電源条件の比較を要するため、M0 では観察と測定手段を記録し、根拠なく電池寿命を推定しない。

## 5. 精度の評価手順

### 5.1 開発用検証

校正後、校正点と異なる位置を提示して推定の誤差を確認する。ここで特徴量や時間窓を調整してよいが、その結果を正式な性能値として報告しない。

推定点を表示して挙動を見る診断モードも、開発用検証として識別する。姿勢を固定して目だけ動かす場合と、同じ点を見ながら頭を動かす場合を試し、頭の動きだけを学習していないか調べる。

### 5.2 正式評価

1. 実装 commit、モデル・特徴量・検出器の版、校正、全設定、環境を固定して記録する。
2. 校正に含まれない座標目標で 20 試行を行う。目標は表示領域の中央と端に分散させ、提示順の seed を残す。
3. 主条件の日本語文章で 60 試行を行う。正解は「対象行内の指定した語」として示し、その語を見て Space を押してもらう。語の中心を目標座標、属する行を正解行として記録する。行の中央だけに偏らせない。
4. 校正を更新せず、同じ検証ページを表示したまま自然に文章を 10 分読んだ後、または自然な姿勢変更の後に、同じ件数の行評価を別条件として実施する。M0 は非表示で停止するため、他タブに移る実験とは区別する。条件を混ぜて正答率を算出しない。
5. 別の収集セッションでも、再校正して同じ手順を繰り返す。セッションを跨ぐ再現性と、無校正での時間変化を区別する。
6. 行間を広げる比較は別条件とする。設定を変えた場合は、別の正式評価を開始する。

各段落に少なくとも 3 行を含む複数段落を使い、全体を初期表示領域内に収める。目標は行・横位置・段落に分散させる。正解の管理は評価側が持ち、推定・候補選択の入力へ渡さない。

Space 後の結果を見て同じ試行を取り直して成功値だけを残すことはしない。中断・失敗も記録し、追加試行は新しい trialId とする。時間経過や姿勢の条件を満たせなかった場合は、未実施として報告する。

20 / 60 試行は初期の観察計画であり、一般利用者への精度保証に十分なサンプル数を意味しない。1 人の結果を他の人や機器へ一般化しない。連続フレームを独立した試行として数えない。

## 6. 集計の定義

開始した試行は、評価側が目標を表示して受け付け状態になった時点で 1 件とする。確定前の明示中止や文脈変更は中断、確定したが使える位置・候補がなかった場合は候補なしとする。

| 指標 | 定義 |
| --- | --- |
| 正解行率 | 正解行になった件数 / 開始した全行試行。候補なし・中断も分母に含める。 |
| 隣接行率 | 同じ段落で上下 1 行の誤りの件数 / 全行試行。別の段落の隣接表示行は含めない。 |
| 正解または隣接行率 | 正解行と同じ段落の隣接行の合計 / 全行試行。正解行率と併記する。 |
| それ以外の行率 | 同じ段落で 2 行以上離れた候補の件数 / 全行試行。 |
| 別段落率 | 別の段落になった件数 / 全行試行。 |
| 候補なし率 / 中断率 | それぞれの件数 / 全行試行。上記の相互排他的な 6 区分の件数合計が総件数と一致する。 |
| 座標誤差 | 有効な代表点と目標の中心の差。絶対縦誤差、絶対横誤差、ユークリッド距離の p50 / p90 / p95。欠損数を併記する。語の中心は実際の注視点の近似である。 |
| 相対縦誤差 | 絶対縦誤差 / 実際の行ピッチ。表示倍率の異なる条件の比較を補助する。 |
| サンプルの古さ | キー処理開始時刻から、採用サンプルの最新・最古の sampledAt までの差。 |
| 推論時間 | producedAt - sampledAt。露光からの真の遅延とは区別する。 |
| キーから表示まで | キーイベント処理の開始から表示更新後の描画機会までの近似値。イベントが処理待ちになった時間や画面の実際の発光までを保証する値ではない。 |
| 校正負担 | 校正の経過時間、有効点数、取り直し回数、利用中に再校正した回数。 |

分位点は、値を昇順に並べて ceil(p × n) 番目を取る nearest-rank 法とする。値がない場合は null。率は分子・分母と合わせて示し、Wilson の 95 % 区間を記載する場合も、少数の本人試行の不確かさを表す参考値として扱う。

## 7. 進める・改善する・保留する判断

M0 では行一致率 95 % や文字単位の精度を合格保証にしない。以前の構想の数値は目標候補であり、達成が確認された条件ではない。

M0 のレポートには、次のどれを選ぶかと根拠を残す。

- **M1 で操作比較を行う:** 校正直後と時間・姿勢変化後の結果から、候補位置からの修正が実際に試す価値のある範囲に収まると判断した場合。
- **M0 を改善して再評価する:** 誤差の方向、姿勢依存、欠損、遅延などに改善すべき原因が見つかった場合。変更内容を記録し、新しい評価データを使う。
- **方式を保留・再検討する:** 行や段落を越える誤りが多い、再校正負担が大きい、負荷が高いなど、想定する操作を改善する見通しがない場合。

M1 の実験開始前には、比較する普段の方法、対象の文章、同じ正解範囲、タイムアウト、許容する誤選択、必要とする時間短縮量を事前に決める。候補はマウス操作、検索からの選択、既存の Vimium-C 操作で、本人が実際に使う方法を基準にする。試行順を入れ替え、成功率・修正キー数・やり直しを含む選択完了時間と、校正負担を比較する。

M2 は fork を使わない独立拡張・キャレット代替・設定 JSON 変換を前提とし、操作範囲の詳細はこの比較で得た結果を基に確定する。計測後に都合の良い指標だけへ変更して、実用成立と扱わない。

## 8. Vimium-C との共存と設定変換

[共存要件と VC-01〜VC-10](vimium-c-coexistence.md) を別の検証群として扱う。設定変換器の純粋ロジックは TDD、実際の取り込みとモードごとのキー制御は、両拡張機能を導入したブラウザで確認する。JSON を作れたことだけで、適用済み・二重実行なしとは判定しない。

視線の品質とは独立に、疑似座標で制御移譲・終了・失敗復帰を試す spike を早期に行う。成立しなければ別の非 fork 方式を検討する。M0 の自動テストの成功を、共存機能の成功に流用しない。
