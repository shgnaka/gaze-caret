# gaze-caret 要件定義

版: 0.1 / 作成日: 2026-09-05 / 状態: 初期要件ベースライン案

本書は、添付の構想と、その後の「視線精度の検証を先に行う」「推定部分の自作を検討する」「専用 GPU や推論 API の追加費用を前提にしない」という会話を具体化したものである。実装・実機測定はまだない。

## 1. 目的と成功の意味

ユーザーが Web ページの文章を見てキーを押すと、視線に近い位置からテキスト選択を始め、キーボードで範囲を調整できるようにする。最終的な対象は Vimium-C である。

製品としての成功は、普段の選択方法に比べて、修正・やり直し・キャリブレーションの負担を含めた操作が楽になることである。視線座標の誤差や行一致率は、その判断に使う中間指標である。

最大の未検証事項は、通常のウェブカメラで実際の文字サイズ・行間を扱えるか、姿勢や時間の変化に耐えられるかである。DOM への吸着や平滑化で、推定に含まれていない精度を保証することはできない。

本書の「必須」は実装の受け入れ条件、「初期値」は変更可能な実験設定、「仮説」は実測で判断する項目を表す。ソフトウェアの完成と視線方式の実用成立を別々に判定する。

## 2. マイルストーン

| 段階 | 作るもの | 完了時に判断できること |
| --- | --- | --- |
| M0: 今回の実装対象 | 単独の検証ページ。カメラ、特徴量抽出、自作の回帰モデル、キャリブレーション、座標・行の評価 | 自分の PC での行一致率、失敗率、遅延、姿勢による悪化 |
| M1: M0 の結果を踏まえる | 通常の DOM テキストへのキャレット配置・選択と、修正操作の計測 | 従来の選択方法より速いか、修正負担が許容できるか |
| M2: M1 の結果を踏まえる | Vimium-C の Visual Mode 起動との連携 | 実際の閲覧で視線による選択開始が使えるか |

M0 に、汎用ページの全文探索、ブラウザ拡張としての常駐、Vimium-C の変更、文字単位の正確な選択は含めない。M0 の行評価は、検証ページ内で位置と正解が分かるテキストを対象にする。

## 3. 対象環境と操作

- 主対象は Windows 11 上の Chrome、通常のウェブカメラ、画面 1 台、ユーザー 1 人。正確なブラウザ・OS・カメラ設定は実験時に記録する。
- Vivaldi は副対象として同じ手動確認を行う。Chrome での結果をそのまま Vivaldi の動作保証にしない。
- 初期検証はブラウザのページズーム 100 %、ピンチズームなし、ウィンドウとカメラの配置を固定して行う。OS の表示倍率は変更せず記録する。
- カメラを利用できる HTTPS または localhost のトップレベルページで実行する。ファイルを直接開く方法や埋め込みプレビューに依存しない。
- 説明・操作 UI は日本語を基本とする。開始、停止、校正、検証、結果保存の順番と、現在の状態が分かること。
- M0 の確定キーは Space。検証エリアにフォーカスがあり、入力・編集欄以外にいる場合にだけ扱う。IME 変換中、修飾キー付き、キーリピートを評価操作として受理しない。
- M2 の目標操作は Normal Mode からの `v`。`c` などの追加割り当ては、その時点の Vimium-C の操作体系に合わせて扱う。

## 4. 必須要件

### 4.1 カメラと実行状態

| ID | 必須動作 |
| --- | --- |
| CAM-01 | ページを開いただけではカメラを要求しない。明示的な開始で映像だけを要求し、音声を取得しない。カメラの選択と使用中表示を用意する。 |
| CAM-02 | 開始要求を重複実行しない。停止・再開始・読み込みの失敗・遅れて返った許可結果を処理し、古い実行のトラックや推定結果を残さない。 |
| CAM-03 | 停止時は、このアプリが取得した全トラックを停止し、推論処理と履歴を破棄する。M0 ではページが非表示になった場合も停止扱いとし、戻っても自動でカメラを開始しない。 |
| CAM-04 | 許可拒否、カメラなし、他アプリとの競合、切断、モデル読み込み失敗を区別して示し、停止または再試行できる。エラー時に正常な推定を装わない。 |

画面の状態は、停止中、起動中、校正が必要、校正中、検証中、利用可能、エラーとして区別する。「利用可能」はモデルから値を取得できる状態であり、行選択の精度を保証する表示ではない。

### 4.2 推定と学習

| ID | 必須動作 |
| --- | --- |
| EST-01 | 初期エンジンは、学習済みの MediaPipe による顔・目の検出と、自作の特徴量処理・リッジ回帰を組み合わせる。回帰の個人用学習は通常の PC の CPU で行える規模にする。 |
| EST-02 | 左右の虹彩の目に対する相対位置と、顔の向き・位置・大きさの手掛かりを扱う。処理画像とプレビューの左右反転、画像座標の縦横スケールを一貫させる。目の開き具合は利用可否の判定にも使う。 |
| EST-03 | 検出・特徴量生成・学習・推定・履歴選択を分離する。推定結果の共通契約を保ったまま、別エンジンを比較できること。特定ライブラリの描画用の点を真の出力として代用しない。 |
| EST-04 | 未学習、特徴量欠損、顔の消失、まばたき、数値異常、複数人など対象外の入力で、有効な位置を捏造しない。特徴量欠損を無条件に 0 で補完しない。 |
| EST-05 | 推論は同時に 1 件まで。処理が追いつかない場合はフレームを間引き、古い仕事を積み上げない。フレーム取得に近い時刻と推論完了時刻をそれぞれ記録する。 |
| CAL-01 | 既知の点を提示し、注視位置と特徴量の組を収集する。点の表示直後の移動時間を除外し、欠損やまばたきを除いた必要数を得られなかった点は取り直せる。 |
| CAL-02 | 全点を偏りなく学習に含める。後半の点の追加で前半の点を押し出さない。前処理の統計量、回帰の係数と切片、特徴量の定義・版、学習条件をモデルと対応づける。 |
| CAL-03 | 学習に使わない位置で検証する。検証・正式評価中はモデルを固定し、クリック、マウス移動、正解ラベル、評価結果から自動学習しない。設定を調整した検証データと、最後に報告する評価データを分ける。 |
| CAL-04 | 校正を取り直せる。カメラ変更や表示領域の座標系の変更後は再校正を要求する。再起動・姿勢変更・時間経過後に精度を確認する導線を用意する。姿勢の変化を完全に自動検知できるとは仮定しない。 |

### 4.3 キー押下時の位置とテキスト行

| ID | 必須動作 |
| --- | --- |
| POS-01 | 出力を、対象の表示領域の左上を原点とする CSS ピクセルに統一する。カメラ画像のピクセルや OS の画面座標と混同しない。画面幅・高さで正規化して学習する場合も、その表示領域との対応を保持する。 |
| POS-02 | 推定履歴を時間・件数の両方で制限する。キー押下時に、その時点で利用可能だった履歴を固定し、押下後に取得・到着したデータで結果を変更しない。 |
| POS-03 | 設定した押下前の時間窓から代表点を選ぶ。初期方式は座標ごとの中央値。サンプル不足、鮮度不足、過大な分散、無効な文脈では「位置なし」と理由を返す。以前の位置を無期限に使わない。 |
| POS-04 | スクロール、テキストの再配置、校正更新、停止、対象文脈の変更で古い履歴を無効化する。単なる文書スクロールと、再校正が必要な表示領域の移動・サイズ変更を区別する。変化中の評価試行を黙って削除しない。 |
| TXT-01 | 実際の CSS と DOM から求めた行の矩形を使い、代表点に最も近い候補行を表示する。初期版は矩形への距離で決め、距離上限と同距離時の規則を固定・記録する。離れた点を必ずどこかの行へ吸着させない。 |
| TXT-02 | 行候補を決める処理に、評価上の正解行を渡さない。代表点の生の座標と、吸着後の行候補の両方を結果に残す。行間や余白を実際に含む日本語の文章で評価し、目標の指示や結果の強調で行の配置を変えない。 |
| TXT-03 | Space で候補行を短く強調し、推定不能なら理由を表示して現在の選択を壊さない。入力欄、ボタンの通常操作、IME 変換、キーリピートとの競合を避ける。 |

### 4.4 評価とデータ

| ID | 必須動作 |
| --- | --- |
| EVAL-01 | 座標誤差、正しい行、同じ段落の隣の行、同じ段落のそれ以外の行、別の段落、候補なし、試行中断を区別する。失敗を分母から除外せず、条件ごとの件数と率を示す。 |
| EVAL-02 | 正式評価中は視線の点・顔プレビューを隠し、モデルを更新しない。推定結果のフィードバックは確定後に出す。診断モードで点を表示した結果は正式評価と混ぜない。 |
| EVAL-03 | 推論時間、データの古さ、キー処理時間、表示反映までの近似時間、実効推定頻度を分けて測る。主張する指標の測定方法と限界を明記する。 |
| EVAL-04 | バージョン付き JSON と試行単位の CSV を明示操作でダウンロードできる。実験・モデル・文脈の識別子、設定、実行環境、成功・失敗・中断の全試行を再集計できる情報を含める。 |
| DATA-01 | 顔や目の画像、映像、音声を保存・送信しない。推定は端末内で完結する。静的なアプリ・モデル・WASM 等の取得は認めるが、取得リクエストへ校正データや視線データを混ぜない。 |
| DATA-02 | 標準ではデータはメモリだけに置き、リロード後に引き継がない。特徴量・目標点・試行結果の書き出しは明示操作に限る。保存したモデルの読込や自動永続化は M0 の必須範囲にしない。 |
| DATA-03 | 短時間の生の視線履歴と、評価のための記録を区別する。正式評価では確定ごとの代表値と判定を保持し、連続した生の視線履歴を長期記録しない。校正特徴量も件数を制限する。 |
| DATA-04 | セッションのデータを破棄できる。破棄・停止の後に古い非同期処理が結果を復元しない。手動で書き出したファイルは、ブラウザ内の破棄操作では削除できないことを示す。 |

### 4.5 実行・配布・検証の再現性

| ID | 必須動作 |
| --- | --- |
| DEV-01 | 推定・個人用学習に有料 API、専用 GPU、常設の学習サーバーを必須にしない。ブラウザ内で個人用学習と利用を行えること。顔・目の検出の実行速度と電池消費は別に測定する。 |
| DEV-02 | 依存関係・実行環境の版を固定し、再現可能なビルドを用意する。実行に必要なモデル・WASM 等も配布物に含め、実行時の可変 CDN URL や暗黙の外部ダウンロードに依存しない。資産の由来・版・利用条件を記録する。 |
| DEV-03 | GitHub Actions で自動検証とビルドを行い、トップレベルに index.html を含む Web 配布物をダウンロードできるようにする。取得から HTTPS または localhost での起動までを README に記す。サイトの公開設定は配布物の作成とは別に扱う。 |
| DEV-04 | 学習に使うデータと、比較条件・乱数 seed・設定・実装の commit を対応づける。自動テストの成功、疑似入力での確認、本人のカメラを使った測定を区別して報告する。 |

## 5. データ契約

以下はコンポーネント間の意味上の契約であり、採用フレームワークやクラス名を固定するものではない。

| データ | 必要な項目と意味 |
| --- | --- |
| 推定サンプル | CSS 座標の x / y、sampledAt、producedAt、contextId、modelId、有効性と無効理由。無効な場合の座標は null とする。 |
| 校正サンプル | 特徴量、目標点の識別子と座標、取得時刻、収集回、文脈と特徴量の版。目標の提示区間に属するフレームだけを対応づける。 |
| モデル | 特徴量の順序・正規化の統計量、回帰係数・切片・設定、学習に使った収集回、文脈、版と識別子。 |
| 押下時の決定 | pressedAt、採用した時間窓、サンプル件数・鮮度・分散、代表座標、候補行または候補なしの理由。 |
| 評価試行 | experimentId / sessionId / trialId、目標を提示した presentedAt、正解、決定結果、判定区分、測定時間、設定、中断や失敗の理由。 |

sampledAt は実際の露光時刻と同じとは限らない。M0 は 1 ページ内の共通の単調時計を使い、フレーム取得に近い時刻の近似であることを記録する。別のページ・worker・拡張機能へ分離する際は時刻基準を明示して変換する。

contextId はカメラ、対象表示領域、その寸法・位置・倍率の条件を識別する。modelId は校正モデルの更新で変わる。文脈の寸法変更時に古い座標を単純に拡大して再利用しない。ページズームと OS 倍率は devicePixelRatio だけで完全に識別できるとは仮定せず、手動の環境記録も使う。

無効理由には、少なくとも未校正、顔検出不可、目の状態不良、特徴量不正、モデル不正、古いデータ、サンプル不足、分散過大、文脈変更、候補距離超過を含める。顔検出の confidence や座標の安定性を「正しい行に当たる確率」として表示しない。

JSON / CSV は個人情報を含まないアプリ内のランダムな識別子を使い、カメラの永続的な deviceId や外部ページの閲覧履歴を出力しない。M0 は検証ページ内の fixtureId と行の識別子で対象を表す。未取得値と 0 を区別し、エクスポート失敗時は再試行できること。

## 6. 初期実装で採用する判断

| 判断 | 理由と見直す条件 |
| --- | --- |
| 顔・目の検出は既存モデル、画面座標の回帰は自作 | 普通の PC で学習を試し、どの段階で誤差が出るか調べやすくする。画像情報の不足が疑われる場合は画像特徴を使う方式を比較する。 |
| 最初の正解対象は行 | 文字単位の誤差を修正できるという構想の前提を先に確認する。行一致だけで製品の使いやすさが成立したとは判定しない。 |
| 学習・推定をブラウザ内で実行 | 初期のサーバー・GPU・API 費用を不要にし、映像を端末内にとどめる。 |
| 実装を始める前に要件由来のテストを作る | ライフサイクル、時刻、学習データの混入、失敗の集計が誤ると実測を信頼できなくなるため。画像モデルの精度は自動テストだけで確認しない。 |
| TypeScript を初期の実装言語とする | UI・ブラウザ API・データ契約を同じ言語で扱う。UI フレームワークや行列計算ライブラリは実装時に選び、固定版と理由を記録する。 |
| WebGazer は比較候補にとどめる | 必須依存にはしない。比較する場合は評価条件、内部平滑化、自動学習、画像パッチの保存、カメラ停止の挙動をそろえる。 |

実験設定の初期値と、その変更・評価の規則は [検証計画](validation-plan.md) を正とする。設定を変更して良い結果だけを選ぶことや、達成できなかった基準を事後に書き換えて合格扱いにすることはしない。

ブランチの使い分け、実装方式の比較、TDD と実機実験の進め方は [開発方針](development-strategy.md) と [CONTRIBUTING.md](../CONTRIBUTING.md) に定める。通常の統合先は `develop` とし、`main` への昇格をリリース時の別の判断として扱う。

## 7. 将来の選択・Vimium-C 連携の境界

| ID | M1 / M2 で満たす境界条件 |
| --- | --- |
| FUT-01 | 表示中の通常の DOM テキストを対象に、Range / Selection でキャレットや選択を配置する。日本語の単語・書記素を考慮し、行・単語・文字の正答率を区別する。 |
| FUT-02 | M2 では Normal Mode からの新規起動時だけ視線位置を適用し、Visual / Caret / Line 間の切り替えや検索からの復帰で開始位置を毎回動かさない。 |
| FUT-03 | 視線なし、古いデータ、低品質、対象テキストなし、権限やページの制限時は通常の Vimium-C の起動経路に戻る。既存選択とキー操作への影響を検証する。 |
| FUT-04 | 連携方式は M1 後に決める。既存の外部コマンド・メッセージの経路とフォーク案を実装で比較する。フォークを唯一の方法として確定しない。 |
| FUT-05 | 拡張機能でカメラを維持する際は、既存 offscreen document の用途・終了処理・権限と統合し、ウィンドウ・タブ・フレーム・時刻の対応を管理する。 |

Vimium-C の確認対象は commit `31885269460a3f0635c7dd69176ed387ad138e96`。新規 Visual Mode の入口と既存 Selection の利用経路は確認できたが、視線連携の実機検証はしていない。Visual Mode の内部では activate の再呼び出しがあるため、入口への無条件な視線処理の追加は上記の境界を満たさない。

## 8. 初期範囲外と、実測で決める事項

初期範囲外は、画像モデル全体の大規模学習、専用アイトラッカー、OS 全体のカーソル操作、スマートフォン対応、複数画面の自動追従、任意のズーム・配置への無校正追従、クロスオリジン iframe、Shadow DOM、縦書き、Canvas、画像内文字、PDF、ブラウザ内部ページ、受動的な自動再学習である。

実測後に決める事項は、必要な校正頻度、最適な特徴量・時間窓・平滑化、許容できる修正量、精度に対する実用判定値、CPU・電池負荷の上限、Vimium-C との連携方式である。初期値を置くことと、その妥当性が実証されたことを区別する。
