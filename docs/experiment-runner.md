# 実験画面・公開・結果共有

作成日: 2026-09-06 / 対象: 最初の実験用 Web アプリ

## 採用する構成

GitHub Pages に静的な実験画面を置く。MediaPipe の顔・虹彩検出、自作の CPU リッジ回帰、校正、評価はブラウザ内で実行する。実験後に集計と感想を確認し、入力済みの GitHub Issue を開ける。投稿は本人が GitHub の画面で確定する。ChatGPT は会話で依頼を受けた時に、その Issue を取得する。常時監視や投稿を契機とするチャットの自動起動は実装しない。

| 方式 | 今回の判断 |
| --- | --- |
| GitHub Pages + Issue の入力済みリンク | 採用。既存リポジトリと認証を使い、ブラウザへトークンを持たせずに結果を渡せる。アプリも Issue も公開になるため、共有する集計と感想を事前に確認する。 |
| Cloudflare Workers + 結果保存 API | 静的配信に加え、認証とデータ保存を実装できる。初回はアカウント連携・認証・保存・削除・取得経路の運用を増やすため保留。非公開の継続的な収集が必要になった場合に再評価する。 |
| localhost + ファイル添付 | 引き続き利用できる。公開アプリと同じビルドを動かせるが、毎回の起動と更新の手間がある。 |

根拠: [GitHub Pages の公開元](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[Issue の URL 入力](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue#creating-an-issue-from-a-url-query)、[Workers の静的配信](https://developers.cloudflare.com/workers/static-assets/)。採否はこの実験の構成と現在の運用負担に基づく判断。

## 実験の流れ

1. 入力、ページ、試行数、休憩間隔、行間、seed を選ぶ。明示操作で実験条件だけをブラウザへ保存できる。
2. カメラを明示的に開始し、大まかな配置、写り方、任意の OS 表示倍率を確認する。デモではカメラを要求せず、マウス位置を視線入力として使う。
3. 実カメラでは画面の 9 点を順番を変えて 2 巡する。300 ms の移動時間を除き、続く最大 1000 ms で各提示 5〜15 件を取得する。不足した点だけ取り直す。全提示の件数を均等化して λ = 1 のリッジ回帰を学習する。
4. 未使用の座標で精度を確認する。動作確認は 5 点、基準測定は 20 点。検証データを学習に使わない。
5. 3 回の練習を行い、操作を確認して本測定を開始する。モデルを固定し、Space の確定後に結果を示して自動で次へ進む。
6. 設定した区切りで休憩し、5 点の独立した再確認を経て再開する。停止、非表示化、配置・表示領域変更は旧データを無効化し、再開に配置確認と校正を要求する。
7. 全試行を含む結果を表示し、JSON / CSV を明示操作で取得する。集計と感想はコピーしてチャットへ貼り付けるか、公開共有に同意して GitHub の入力済み Issue を開く。

デモ結果には DEMO、12 試行の動作確認には quick-check と記録する。これらを視線精度の基準測定と混同しない。顔プレビューと視線点を正式評価中に表示しない。候補なし・中断も集計の分母に含める。練習と座標検証は本測定の行一致率に含めない。

デモのマウス位置は画面更新ごとに採取し、実カメラの上限 15 Hz の推論とは区別する。デモは操作と DOM 選択を切り分けるための対照入力であり、実カメラの欠損・負荷・時間特性を再現するものではない。

配置と校正の基本条件は ENV-01〜ENV-06、既知のページの基準は LAY-01〜LAY-06 を引き継ぐ。今回の fixture は 1 段組、本文とサイドバー、カードと内部スクロールである。任意の CSS・iframe・Shadow DOM・実サイト一般への対応完了とは扱わない。

## データと測定の境界

- 映像・音声・顔画像は通常の診断では記録・送信しない。映像フレームは推論後に破棄する。基本診断は顔数・拒否理由・処理時間を集計し、詳細診断を明示的に選んだセッションだけ、正規化ランドマークと派生特徴量を上限付きで端末メモリに保持し、手動 JSON 出力できる。
- 初期の検出はメインスレッドで同期実行し、上限 15 Hz とする。推論の近似時間・フレーム数を JSON に記録する。実機での UI 停滞や CPU 負荷は別に測る。Worker 分離や電池寿命の評価が完了したとは扱わない。
- 試行にはモデル・校正文脈・レイアウト更新・viewport を対応づける。表示領域の変更後に古い座標を拡大して再利用しない。M0 の非表示時停止を維持する。
- 明示的に保存できるブラウザの設定は入力方式・ページ・件数・休憩間隔・行間・seed だけ。モデル、校正、映像、視線、結果、感想を自動永続化しない。この設定保存だけを DATA-02 のメモリ内既定からの明示的な例外とする。
- Issue の入力済みリンクには実験集計と基本診断の集計だけを含め、連続視線・詳細ランドマーク・詳細特徴量・画像・永続的な deviceId を含めない。公開共有の同意前はリンクを生成しない。詳細 JSON は本人が共有先を選べる。
- 公開アプリへ GitHub の PAT や API キーを置かない。Issue 作成に使う認証は GitHub 自身が扱う。
- 一時停止後は結果を保持するが、ページを閉じたりリロードすると消える。終了時にダウンロードする。再実験の前には未保存の結果の破棄を確認する。

## 診断ログの回収

診断ログは `basic` と `detailed` に分ける。`basic` は顔数、特徴量の拒否理由、推論時間、映像未準備などの集計だけを保持する。`detailed` は同じ集計に加えて、直近の正規化ランドマーク、派生特徴量、推定点、校正・検証の相対時刻を保持する。どちらも画像、音声、認証情報、deviceId、ローカルパスを含めない。

カメラ準備画面には、校正前の失敗でも使える「診断ログをダウンロード」操作を置く。結果画面では実験結果 JSON と診断ログ JSON を個別に取得できる。公開 Issue の下書きには `basic` の公開用スナップショットだけを含め、詳細ログは手動で保存・共有する。

外部への自動送信は、受信 API、認証、保存期間、削除方法が確定するまで呼び出さない。GitHub Pages のクライアントへ GitHub の PAT や Cloudflare の秘密情報を配置しない。Cloudflare Workers / R2 の設定後は、現在の診断 JSON を送信する transport を追加し、送信の同意・再試行・重複防止を別のテストで固定する。

## TDD と受け入れ

純粋ロジックは、既知の回帰、収集点の均等化、時間窓、履歴の上限、早すぎる・連続したキー、休憩、再確認、中断の分母、別領域の分類、顔・目の拒否理由、診断集計、公開用集計を振る舞いのテストから実装する。

カメラの許可待ちやモデル読込中に停止するテストでは、遅れて取得した全トラックと検出器を解放し、新しい実行へ混ざらないことを確認する。

実ブラウザではデモの全経路、校正前の詳細診断ダウンロード、休憩と再確認、結果の出力と公開同意、カメラ拒否、表示領域の変更による中断、サイドバーの選択、設定保存、偽カメラを用いた同梱モデル・WASM の起動と停止を確認する。偽カメラの成功は本人の視線精度の証明にしない。実行結果は PR と CI を参照する。

## 公開ブランチ

`main` と `develop` は従来の役割を維持する。`feat/experiment-runner` は最初の TDD 実装 PR に依存する Draft PR とする。`experiment` は検証済みの実験版を選ぶ配信専用ブランチであり、独立して製品実装を進める統合先にはしない。

`experiment` の更新でチェック、ビルド、ブラウザテストを行い、成功した成果物だけを GitHub Pages に配信する。未統合の実験版を配信しても、`main` にマージしたことや製品リリースの成立を意味しない。PR の通常の CI では配布用 ZIP を作成し、公開は行わない。

最初の 1 回だけ、リポジトリの Settings → Pages → Source を GitHub Actions に設定する。`github-pages` 環境に許可ブランチ制限がある場合は、実験配信用の `experiment` を許可する。Pages の初回有効化には管理設定へのアクセスが必要であり、標準のワークフロートークンでは自動有効化できない。[公式 configure-pages の入力定義](https://github.com/actions/configure-pages/blob/983d7736d9b0ae728b81ab479565c72886d7745b/action.yml)

公開完了は Pages の成功した deployment と URL の確認で判定する。URL の推測やビルドの成功だけで公開済みとは報告しない。
