# 推定コアの数値安定性・特徴量判定・推論周期

実施日: 2026-10-23 / 対象: EST-01 / EST-02 / EST-04 / EST-05、A-03 / A-04 / A-05 / A-09 の計算部分

## 変更と根拠

### リッジ回帰

`fitRidge` は正規方程式の消去法から、Givens 回転による QR 最小二乗法へ変更した。標準化した観測行へ特徴量ごとの `sqrt(lambda)` の補助行を追加する。切片は罰せず、両画面座標へ同じ直交変換を適用する。目的関数、既定の `lambda = 1`、点ごとの校正件数の均等化、モデルの入出力形式は維持する。

正規方程式を作ると特徴量の相関による悪条件性が増幅され、小さい正則化が丸めで失われる。重複列と `lambda = 1e-14` の人工例では、学習時の列の関係から外れる入力 `[0.5, 0]` に対して解析解が約 `(5.75, 6.5)` であるのに、旧方式は約 `(5.754503, 6.505873)` を返した。QR では各軸の誤差が `1e-8` 未満という受け入れ例を満たす。これは既知の人工問題の数値誤差であり、本人の視線誤差ではない。

学習統計量や係数が非有限になる場合は `RangeError` とする。`predict` はモデルの次元、有限値、正のスケール、欠損を確認し、不正なら例外や座標の代わりに `null` を返す。計算量は観測数 N・特徴量数 d に対して O(Nd²)、作業メモリは O(d²)。極端な入力で表現可能な数値範囲を超える場合まで解けるとは保証しない。

### 閉眼・映像寸法の判定

上下まぶたの単純な距離には、目の横方向のずれが混ざっていた。目頭・目尻の軸へ垂直な開口幅を使うことで、横にずれただけの閉眼を有効な特徴量として学習・推定へ渡さない。判定閾値は目の幅の 8% を維持する。左右両眼、傾斜、640×480 の映像で、独立に指定したピクセル幾何から検証した。

12 個の特徴量の値・順序は変更しておらず、`iris-head-12-v1` は維持する。有効・無効を分ける規則が変わるため、比較には実装 commit も使う。無限大の映像寸法は `invalid-frame` として拒否する。実カメラでの拒否率は未測定。

### 推論の予定時刻

`InferenceScheduler` を純粋なコアへ分離し、画面更新の時刻を渡して処理機会を決める。開始時刻と整数の期限番号から 15 Hz の予定時刻を求め、前回の実行時刻へ毎回丸め直すことで頻度が落ちる問題と、小数周期の反復加算による長時間のずれを防ぐ。

最初の処理機会は即時。1 周期以上遅れた場合はその時刻から予定を立て直し、未処理の過去の期限をキューへ積まない。1 回の画面更新で推論は最大 1 件、同じ動画時刻の重複処理も引き続き避ける。部分的な遅れや表示周期への丸めにより、隣接する処理間隔は 66.7 ms より短い場合もある。これは厳密な最小間隔の制限ではなく、平均 15 Hz の予定である。

遅い推論、映像更新の停止、無効フレームがあれば有効な頻度は下がる。200 ms 窓の全位相で必ず 3 件を得られるとは保証しない。時間窓・最少件数・分散の閾値を緩めず、足りない場合は従来どおり位置なしにする。

## 実測との境界

本人のカメラによる校正・精度・負荷の測定は実施していない。新しい特徴量の追加や回帰の複雑化、正則化・時間窓の調整はしていない。これらを精度改善として選ぶには独立した実測データが必要である。今回の変更は、再現できる計算誤差、無効入力の扱い、処理予定の不具合を直すものとして評価する。
